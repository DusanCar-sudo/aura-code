Execution Loop

The process is the product.

This direction makes Aura feel like engineering infrastructure instead of a mascot page. The visual system is built from job queues, traces, and verification logs.

01 / read

Map the repo

Files, conventions, dependencies, and unknowns are gathered before edits begin.

02 / plan

Choose the move

The plan names what changes and what stays untouched.

03 / execute

Patch precisely

Small diffs, local style, and no unrelated cleanup.

04 / verify

Run checks

Tests and builds are treated as evidence, not ceremony.

05 / report

Show receipts

File paths, line numbers, and the exact validation result.

Persistent Memory

Aura starts the next task warmer.

The redesign treats memory as working context, not as a vague AI promise. It shows decisions, lessons, and constraints as records the agent can reuse.

decision

Use TypeScript boundaries for provider adapters; avoid pushing vendor logic into the CLI loop.

lesson

Verification output must be summarized with command names and failures, not hidden behind confidence language.

context

Current project favors `rg`, focused patches, and explicit final file references.

risk

Do not mutate unrelated worktree changes while improving one surface.

Install

Run it where the repo lives.

This option keeps the conversion point technical and direct: install, configure a provider, then ask Aura to handle a real task.

$ npm install -g aura-code
$ aura "fix the failing auth test"
$ aura --model local "review this PR"
