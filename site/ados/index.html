Finally, your own OS on your own laptop: running what you need, nothing you don't. Aura built it for herself. She installs, themes, fixes and backs it up, and before she changes anything she takes a snapshot you can roll back to.

Why adOS

A desk for developers and their agents.

A dev OS, not a polished one: text over icons, square panes, and the numbers that matter one glance away. If it doesn't help you ship, it isn't on screen.

  1. 1

    She operates it

    Aura, the agent from Aura Code, is the operator. She installs packages, applies themes, fixes what broke and keeps the backups, through a small set of aura-os-* commands that are the only way she may change the system.

  2. 2

    Snapshot first

    Root is btrfs with snapper. Every system change is preceded by a snapshot, and aura-os-reset takes the system back to any of them. Your files in /home are never rolled back with it.

  3. 3

    Under 350 MB, runs everything

    A bare sway desktop that idles under 350 MB, and still runs what you run today: browsers, dev tools, media and games.

  4. 4

    Agents are first-class

    Any agent that speaks MCP gets the desktop through aura-os-mcp: read tools and reversible actions, no shell, and every call logged with the agent's name.

The desk

Text over icons. Square panes.

Sway tiles every window, and the bars around them are plain text in one font. The sidebar is where you look to see what the machine, and every agent on it, is doing right now.

Top bar
Desktop tabs, each renamable and in its own colour. In the centre, the toggles: silent · hotspot · record · cast · tiles.
Sidebar
Every space, live cpu, ram, gpu and power, minimized windows, the last things you used, and each agent's latest step.
Super Enter
A terminal.
Super D
The app menu. Every app, Aura's included, has an entry.
Super Esc
Reboot, power off, log out, or reboot into the firmware setup.

aura-term

A terminal that knows what failed.

aura-term is a fork of foot 1.28 in server mode: one aura-termd for every window, about 2 MB per window. It also knows where each command starts and ends, so it can hand the last failure straight to Aura.

Her answer opens in a split beside the terminal, never inside the running program. A command she suggests is shown and runs only when you press Enter.

Ctrl Shift A
Ask Aura about the selection, or else the last failed command.
Ctrl Shift ↑ ↓
Jump to the previous or next command block.
Ctrl Shift Y
Copy the last command's output.
Ctrl Alt arrow
Split: a new terminal on that side, in the same directory.

aura-os-mcp

Agents get an API, not a shell.

A local MCP server over stdio. It runs only while an agent is connected, with no daemon, and it writes every call, with the agent's name, to ~/.local/state/aura-os/mcp.log.

CONNECT AN AGENT
# Claude Code; any stdio MCP client works the same way
$ claude mcp add --scope user aura-os -- /usr/local/bin/aura-os-mcp

Boot

It even boots in character.

The splash is baked into the unified kernel image, so the firmware hands straight over to it: the lockup lit like a phosphor screen, scanlines and all.

systemd-boot's stub centres a splash unscaled on black, and shows nothing at all if it is bigger than the screen. So this one is 1280 × 720 with pure-black edges: it fits every screen from 720p up, and melts into the black on all of them.

Your model, your key

The API key is the owner's responsibility.

The installer can ask for a base URL, a model and an API key: any OpenAI-compatible endpoint, cloud or local. Skip it and add one later. The key is written for that user only, to ~/.aura/.env with mode 600.
